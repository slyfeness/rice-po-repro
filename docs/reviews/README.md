# GitHub 阶段审核交付规则

每个需要人工审核的阶段使用独立分支和 PR，不直接推送或合并主分支，不开启自动合并。审核上传不代表实验通过，也不授权下一阶段计算、资产下载或依赖安装。

本轮基线为 `validation/first-smoke` 的 `6f878583fa90dcf5ee975a5098a3851ef481a230`。首次材料位于 [first-smoke/](first-smoke/SUMMARY.md)，审核分支为 `review/first-smoke-evidence`，PR 目标为 `validation/first-smoke`，便于只审核本次材料差异。未来阶段应先确认远端最新有效基线与工作区状态，保留未提交修改和既有产物。

阶段目录按实际内容提供 SUMMARY、ENVIRONMENT、DATA_AUDIT、RETRIEVAL_AUDIT、TEST_RESULTS、OPEN_ISSUES；没有实质内容的文件可省略。每项结论绑定源码函数、配置、实际执行的脱敏命令、版本、结果和产物 SHA-256。历史结果与本次重新执行分开记录，状态使用已通过、失败、跳过、未运行，部分诊断不称为完整基准。

原始产物保存在独立集群项目的大容量存储。公共材料仅含小体积、可公开的自有文字、源码、脱敏统计与哈希清单。模型、原始数据、完整轨迹、检查点、凭据、账户、真实地址、内部网络、内部路径、主机标识和未经授权的日志不得上传。无法确认可公开的材料先排除，写明原因。

上传前执行并记录：

1. 检查当前差异和全部待提交文件，排除二进制资产、大文件和意外文件。
2. 扫描敏感字符串、地址、用户目录和凭据模式；人工复核脱敏内容。
3. 检查许可证及第三方文件差异；不新增许可证或转发许可不明的原始内容。
4. 校验公开材料清单和 SHA-256，区分本地静态检查与历史运行测试。
5. 提交到独立分支，创建 PR，核对远端 SHA 与 PR 的 head/base、开放状态。返回分支、PR、提交、材料目录和重点问题。

本目录无自动执行脚本或 CI。原始 Slurm 标识与本地路径只在私有控制面映射到公开证据别名。
