GRPO 第三批唯一正常完成轨迹的最后真实 NDCG@10 为 1.0；其余终态训练效用为 0。正/负/零优势生成 token 分别为 1,348 / 4,667 / 12,989。ratio min/mean/max 均为 1，参考 KL 为 0，截断生效比例为 0；一次整批参考更新中这不是失败标准。参数探针最大变化 `9.5367431640625e-7`，完整权重身份也发生变化。这是 GRPO 的首次奖励驱动更新，不能称为 RICE-PO 已有效学习。

包括失败原尝试在内，本阶段实际调用 optimizer.step 共 5 次：RICE 1 次、原 GRPO 1 次、恢复 GRPO 3 次。原 GRPO 的首批零信号步骤在新恢复运行中重建，不计作额外独立训练样本；只有恢复运行第三批出现非零奖励驱动更新。

RICE 首批四个查询实际选中 13 个合法锚点，五个新分支全部保留，共 65 条；5 条正常到五轮，60 条非法终止。30 条在锚点处无合法 Summary，局部奖励未定义；另 35 条有真实锚点局部奖励（含后续失败的分支）。每个锚点至少缺一个局部奖励，因此 **0/13 可估计，0 次局部替换，0 次推理传播**。没有为这些组计算正式方差或门控通过率。该更新完全回退到轨迹级 GRPO，且原始终态奖励全为 0。依授权条件停止扩大 RICE 训练，没有反复换种子、筛分支或降低门控。

两方法首批完整原始轨迹 JSON 的 SHA-256 一致：`8e083c00de6856710e627073e29534f1b7bcb78af24cf7762e6a13b5a088c30a`。真实最后排名分数包含 0.3154648768、0.6309297536 和 1.0；失败效用仍单独为 0，未继承这些 NDCG。

## 解析修复与保存输出恢复

GRPO 初次作业 174259 在首批零信号更新和检查点验证后，于下一批遇到前缀解码歧义。保存的 872 个原生 token 中，“正”的 UTF-8 字节跨 token；部分前缀出现 U+FFFD，完整字节拼接却与完整文本严格相等。现有 `native_body_coverage_v1` 改为精确原生 ByteLevel 字节区间映射；不补标签、不重分词，不新增坏结构特例，严格参考路径不变。

CPU 174267 使用冻结 tokenizer 比较 40 个保存输出：24 个原先合法动作的文本和区间完全相同，15 个坏结构仍拒绝，仅修复 1 个映射误报；40 个严格参考结果完全不变，原始轨迹 SHA 不变。失败响应原件 SHA-256：`1e4f0f749f5e53d0fc183a0bbe5ddabaac3be71a3088d8481f535a6ba6a9cf75`。

恢复作业 174268 从初始模型开始，仅在配置、配方、数据、模型、tokenizer、检索器、提示、行为策略、种子和完整原生前缀均匹配时复用原作业已保存的响应；第一批重新执行同一个零信号优化器步骤以重建其状态，没有再次生成该批。这是明确记录的恢复实验，非额外独立在线样本；重放生成 token 成本记为 0，检索和评分的实际重复计算仍计入成本。之后缺少保存响应的请求才真实在线生成。
