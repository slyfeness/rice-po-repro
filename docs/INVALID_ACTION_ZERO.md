# Independent zero-utility failure environment

`invalid_action_terminal_zero_v1` is explicitly authorized by the user and is not an author-confirmed paper setting. The strict `raise` path and historical inherited-ranking proposal remain available for comparison; inherited D0/last-ranking reward is rejected for this run.

A malformed or length-exhausted action terminates the actual interaction immediately. All native generated IDs remain actions with direct PPO loss. No missing Summary, ranking, future tokens or observations are fabricated. `final_reward=0` is failure training utility; `last_valid_ndcg` preserves the last real retrieval score and `failure_terminal_reward=0` records the distinct convention.

Four scheduled originals remain in every query group. Only existing valid Summaries can be entropy anchors (up to four). Each selected anchor still has five new independently seeded branches plus the original once. A failed action at the anchor has undefined `local_reward=null`. Any undefined local reward makes the entire anchor `not_estimable`; no subset variance or local replacement is computed. Later failures retain measured anchor NDCG and have terminal utility zero. Estimable groups use unchanged population moments, final-minus-local residuals, 0.05/0.03 gates and replacement formulas. Complete initial and final branch histories are persisted.

Evaluation counts every frozen development identity. Failed query rows have `ndcg_at_10=null`, a separate zero `failure_adjusted_task_score`, last real ranking and NDCG. Aggregate `macro` is explicitly labeled `metric=failure_adjusted_task_score`; complete legal coverage, legal final NDCG distribution and D0 macro are reported separately. This score is not paper NDCG performance.

The bounded configurations freeze the prefilled compatibility prompt, native multi-turn protocol, summary-only query choice, temperature 1/top-p 1/top-k 0, full-vocabulary entropy/KL, LR 1e-6 and KL coefficient 0.001. Four queries per update are a diagnostic budget. Three updates require private runtime bindings and explicit execution authorization; public execution remains disabled. Save/reload each checkpoint and evaluate all 32 development queries at update three (or the configured final update). If an update has zero estimable RICE anchors, preserve its checkpoint and stop expansion with `stopped.json`, without publishing a completed run.

Two independent Slurm allocations each use two visible CUDA devices (actor/reference logical 0, Diver logical 1). Weight and optimizer objects and run directories are independent. This does not implement or validate four-rank distributed training. Cumulative GPU allocation time, including initialization, failures and evaluation, is charged against the authorized 32 GPU-hour cap; 1.072222 GPU hours precede this phase.
